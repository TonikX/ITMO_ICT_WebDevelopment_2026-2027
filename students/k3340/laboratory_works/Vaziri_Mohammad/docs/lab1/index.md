## Задание 1. Обмен сообщениями по UDP

Клиент отправляет серверу «Hello, server», сервер выводит сообщение и отвечает «Hello, client».

UDP работает без установки соединения: сервер вызывает `recvfrom`, получает данные **и адрес отправителя**, и отвечает на этот адрес через `sendto`.

```python
# server.py
with socket.socket(socket.AF_INET, socket.SOCK_DGRAM) as sock:
    sock.bind((HOST, PORT))
    while True:
        data, addr = sock.recvfrom(1024)
        print(f"От {addr}: {data.decode('utf-8')}")
        sock.sendto("Hello, client".encode("utf-8"), addr)
```

```python
# client.py
sock.settimeout(5)   # UDP не гарантирует доставку
sock.sendto("Hello, server".encode("utf-8"), (HOST, PORT))
data, _ = sock.recvfrom(1024)
```

**Результат:**

```
# сервер
UDP-сервер слушает 127.0.0.1:9091
От ('127.0.0.1', 33681): Hello, server
# клиент
Ответ сервера: Hello, client
```

## Задание 2. Вычисления через TCP (вариант 2 — квадратное уравнение)

Пользователь вводит коэффициенты `a`, `b`, `c`; клиент отправляет их серверу одной строкой `"a b c"`, сервер решает уравнение `ax² + bx + c = 0` и возвращает ответ.

Сервер обрабатывает все случаи: два корня (`D > 0`), один корень (`D = 0`), отсутствие действительных корней (`D < 0`, выводятся комплексные), а также вырожденный случай `a = 0` (линейное уравнение).

```python
def solve_quadratic(a, b, c):
    if a == 0:
        if b == 0:
            return "Бесконечно много решений" if c == 0 else "Решений нет"
        return f"Линейное уравнение, x = {-c / b:g}"
    d = b * b - 4 * a * c
    if d > 0:
        x1 = (-b + math.sqrt(d)) / (2 * a)
        x2 = (-b - math.sqrt(d)) / (2 * a)
        return f"D = {d:g}; два корня: x1 = {x1:g}, x2 = {x2:g}"
    if d == 0:
        return f"D = 0; один корень: x = {-b / (2 * a):g}"
    ...
```

Клиент проверяет ввод: если введено не число, просит ввести ещё раз.

**Результат:**


## Задание 3. HTTP-сервер, отдающий HTML-страницу

Сервер читает файл `index.html` и отправляет его в виде корректного HTTP-ответа. Ответ собран вручную и состоит из строки статуса, заголовков, пустой строки и тела:

```python
def build_response(body: bytes) -> bytes:
    headers = [
        "HTTP/1.1 200 OK",
        "Content-Type: text/html; charset=utf-8",
        f"Content-Length: {len(body)}",
        "Connection: close",
    ]
    return ("\r\n".join(headers) + "\r\n\r\n").encode("utf-8") + body
```

`Content-Length` считается в **байтах** (для кириллицы в UTF-8 байтов больше, чем символов), поэтому длина берётся от уже закодированного тела.

**Результат** (ответ на `GET / HTTP/1.1`, страница открывается в браузере по адресу `http://127.0.0.1:8080`):

```
HTTP/1.1 200 OK
Content-Type: text/html; charset=utf-8
Content-Length: 356
Connection: close
```

## Задание 4. Многопользовательский чат (TCP + threading)

**Сервер.** Для каждого подключения создаётся отдельный поток. Первое сообщение клиента — его имя. Сервер хранит словарь `{сокет: имя}` и пересылает каждое сообщение всем остальным участникам. Доступ к словарю защищён `threading.Lock`, так как его меняют разные потоки.

```python
def handle(conn):
    name = conn.recv(1024).decode("utf-8").strip() or "Аноним"
    with lock:
        clients[conn] = name
    broadcast(f"* {name} присоединился к чату", conn)
    while True:
        data = conn.recv(1024)
        if not data:
            break
        text = data.decode("utf-8").strip()
        if text == "/exit":
            break
        broadcast(f"[{name}]: {text}", conn)
    remove(conn)   # удаляем клиента и сообщаем остальным
```

**Клиент** — один скрипт для всех пользователей: имя вводится при запуске. Приём сообщений работает в отдельном потоке, поэтому пользователь может одновременно писать и читать. Команда `/exit` — выход из чата.

**Результат** (два клиента, Rasam и Anna):

```
Rasam: Добро пожаловать, Rasam! Для выхода введите /exit
Rasam: * Anna присоединился к чату
Anna:  [Rasam]: Привет всем
Rasam: * Anna вышел из чата
```

## Задание 5. Веб-сервер с обработкой GET и POST

- `POST /` с полями `discipline` и `grade` (форма `application/x-www-form-urlencoded`) добавляет оценку.
- `GET /` возвращает HTML-страницу с таблицей всех оценок и формой добавления.

Оценки хранятся **сгруппированно**: одна запись на дисциплину со списком оценок.

```python
grades: dict[str, list[str]] = {}
...
grades.setdefault(discipline, []).append(grade)
```

Сервер сам разбирает запрос: строку запроса (метод и путь), заголовки и тело. Тело дочитывается по заголовку `Content-Length`. После успешного POST сервер отвечает `303 See Other` с `Location: /`, и браузер открывает обновлённую страницу. Для неизвестного пути возвращается `404`, для пустых полей — `400`.

**Результат** после трёх POST-запросов (Математика — 5, Математика — 4, Физика — 3):

| Дисциплина | Оценки |
|---|---|
| Математика | 5, 4 |
| Физика | 3 |

## Вывод

В работе реализованы клиент-серверные приложения на сокетах:

- UDP передаёт отдельные датаграммы без соединения, поэтому сервер отвечает на адрес из `recvfrom`, а клиенту нужен таймаут;
- TCP устанавливает соединение и гарантирует доставку и порядок данных, поэтому на нём построены вычисления, чат и HTTP;
- HTTP — текстовый протокол поверх TCP: ответ можно собрать вручную из строки статуса, заголовков и тела;
- для одновременной работы нескольких клиентов сервер чата обслуживает каждого в отдельном потоке, а общие данные защищает блокировкой.
