# Практики 2.1–2.3

Практики представлены общей конечной реализацией в отдельном приложении `project_first_app`, подключённом к лабораторному проекту. Это позволяет показать весь функционал без трёх несовместимых копий пользовательской модели. Файлы и интерфейсы разделены по назначению; фамилию в имени проекта необходимо подставить перед сдачей (см. README).

## Практика 2.1

- Создан Django-проект и приложение с требуемым именем `project_first_app`.
- Из рисунка 2 реализованы автомобиль, владение, водительское удостоверение и владелец. Владелец расширен до User на этапе 2.3.
- Все таблицы зарегистрированы в admin; исходные миграции включены.
- FBV `owner_detail` выбирает владельца по id и отдаёт шаблон `practice/owner.html`; URLconf приложения подключён через include.
- `seed_demo` создаёт 6 пользователей и 7 автомобилей. Первые два пользователя связаны с первыми тремя автомобилями последовательно: 2020–2021 и 2022–2023. Пересечений по датам нет.
- Чтобы продемонстрировать именно ручную работу с admin, войдите созданным суперпользователем, добавьте двух владельцев и четыре автомобиля, затем по три записи владения на владельца без пересечений. Автоматическое наполнение не выдаётся за ручное выполнение пользователем.

## Практика 2.2

- `Car.owners = ManyToManyField(..., through='Ownership')`.
- У Ownership есть даты начала и окончания; незавершённое владение допускает NULL.
- Список и создание владельцев — функции `owners`, `owner_create`.
- Список/карточка/создание/изменение/удаление автомобилей — ListView, DetailView, CreateView, UpdateView, DeleteView.
- Формы — `RegistrationForm` и `CarForm`.
- Автотест `test_practice_owner_fbv_and_car_cbv` действительно отправляет формы создания трёх владельцев и трёх автомобилей, затем проверяет изменение и удаление. Данные теста находятся в изолированной БД и не остаются в демонстрационной базе.
- Для показа преподавателю добавьте через интерфейс ещё три записи каждого типа; начальные demo-данные уже присутствуют.

## Практика 2.3

- `accounts.User(AbstractUser)` содержит паспорт, адрес, национальность, дату рождения.
- `AUTH_USER_MODEL` настроен до первой миграции.
- ForeignKey и ManyToManyField используют `settings.AUTH_USER_MODEL`; view получает класс через `get_user_model()`.
- Новые поля включены в CustomUserAdmin и формы создания пользователя.
- Список и карточка владельца работают с расширенными пользователями.

## Самостоятельная демонстрация

Создайте superuser, проверьте доступность всех моделей в `/admin/`, откройте раздел «Практики», добавьте владельца, создайте автомобиль, измените его цвет и удалите через подтверждение. В admin создайте владение и попробуйте ввести пересекающийся период: форма выдаст ошибку. В карточке владельца проверьте новые атрибуты и водительское удостоверение.
