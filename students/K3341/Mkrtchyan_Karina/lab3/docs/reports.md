# Аналитические запросы

## Запросы варианта 2

| Путь `GET` | Результат |
|---|---|
| `/api/readers/{id}/current-books/` | Текущие невозвращённые выдачи заданного читателя |
| `/api/reports/loans-older-than-month/` | Невозвращённые выдачи строго старше календарного месяца |
| `/api/reports/rare-book-loans/` | Текущие выдачи изданий, которых в фонде не более двух экземпляров со статусом `ACTIVE` |
| `/api/reports/readers-under-20/` | `reader_count`: число действующих читателей младше 20 лет |
| `/api/reports/reader-demographics/` | `reader_count`, `education_percent` по всем категориям и независимый `degree_percent`; знаменатель — действующие читатели, при пустой выборке — 0% |
| `/api/books/{id}/copies-by-room/` | `id_room`, `room_number`, `name`, `copy_count` для всех залов: только действующие размещения экземпляров из фонда. Доступно всем с токеном |

Запросы выдач возвращают массив объектов с `id_loan`, `reader_id`, `reader__full_name`, `copy_id`, `copy__book_id`, `copy__book__title`, `issued_at`, `due_at`. Остальные запросы, кроме подсчёта экземпляров конкретной книги, требуют прав сотрудника.

## Месячный отчёт

`GET /api/reports/monthly/?month=2026-07` (только сотрудникам). Неверный или отсутствующий месяц — `400`.

- `month` — отчётный месяц; `days` — строка отчёта на каждую дату, включая нулевые дни, с `date`, `copy_count`, `reader_count`, `rooms`.
- Состояние на конец дня: экземпляры подсчитываются по действующим размещениям, читатели — по регистрации и истории закрепления за залами, а не по посещаемости. Итог библиотеки включает всех действующих читателей, в том числе без зала, и все уникальные экземпляры с действующим размещением. Текущий статус экземпляра не используется для реконструкции прошлого.
- `registrations` содержит `reader_count` по библиотеке и `rooms` с количеством впервые записавшихся за месяц. Каждый читатель засчитывается в свой первый зал не более одного раза; читатели без истории зала входят только в общий итог.
- Элементы `rooms` содержат `id_room`, `room_number`, `name` и соответствующие счётчики.

## Дополнительные отчёты

Доступны сотрудникам через `GET` с токеном и возвращают массив JSON.

| Путь | Что считает | Поля результата |
|---|---|---|
| `/api/reports/popular-books/` | До 10 книг с наибольшим количеством выдач всех экземпляров за всё время; книги без выдач исключены | `id_book`, `title`, `loan_count` |
| `/api/reports/stock-by-section/` | Число изданий и экземпляров со статусом `ACTIVE` по разделам, включая пустые разделы | `id_section`, `name`, `book_count`, `active_copy_count` |
| `/api/reports/overdue-by-reader/` | Число невозвращённых выдач с истёкшим сроком по читателям; читатели без просрочек исключены | `reader_id`, `overdue_count` |
| `/api/reports/copies-by-room/` | Число уникальных экземпляров, размещённых в каждом зале на заданный момент, включая пустые залы. Используется история размещения, а не текущий статус экземпляра | `id_room`, `room_number`, `name`, `copy_count` |

Для отчёта по залам параметр `at` необязателен (по умолчанию текущее время). Пример: `GET /api/reports/copies-by-room/?at=2026-07-01T12:00:00Z`. Запись учитывается, если `valid_from ≤ at < valid_to` или `valid_to` не указан и `valid_from ≤ at`. Неверный формат `at` даёт `400`.
