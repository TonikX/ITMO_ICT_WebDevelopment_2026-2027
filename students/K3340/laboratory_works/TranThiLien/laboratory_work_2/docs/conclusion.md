# Вывод

## Итоги работы

В ходе выполнения лабораторной работы №2 были изучены и практически освоены основные возможности веб-фреймворка **Django 6.1**.

### Практическая работа 2.1

- Освоена установка Django через виртуальное окружение `venv`.
- Создан проект `django_project_tran` и приложение `project_first_app`.
- Реализована модель данных об автовладельцах: `CarOwner`, `Car`, `Ownership`, `DriverLicense`; использованы `ForeignKey` и поле выбора `choices`.
- Выполнены миграции, все таблицы зарегистрированы в административной панели.
- Через админку добавлены 2 владельца и 4 автомобиля с непересекающимися периодами владения.
- Реализовано первое представление (FBV) и маршрут URL: `/owner/<id>/`.

### Практическая работа 2.2

- Связь «многие ко многим» между автомобилем и владельцем оформлена через ассоциативную сущность `Ownership` (`through`) с датами начала и окончания владения.
- Реализованы вывод и форма ввода владельцев на основе функций (FBV).
- Реализованы вывод всех автомобилей, вывод по id, создание, обновление и удаление на основе классов (CBV: `ListView`, `DetailView`, `CreateView`, `UpdateView`, `DeleteView`).
- Разработаны формы на базе `ModelForm` и `UserCreationForm`, шаблоны с наследованием от `base.html`.

### Практическая работа 2.3

- Изучены 4 способа расширения пользователя; выбран `AbstractUser`.
- «Владелец автомобиля» сделан пользователем: добавлены номер паспорта, домашний адрес и национальность.
- Модель подключена через `AUTH_USER_MODEL` до первой миграции.
- Новые поля отображаются в Django Admin (`UserAdmin` с дополнительными `fieldsets`).
- Страницы из практик 2.1–2.2 выводят информацию о пользователях; реализован интерфейс создания пользователя с новыми атрибутами.

### Вариант 5 — Список научных конференций

Полностью реализован функционал согласно заданию:

- регистрация новых пользователей;
- просмотр конференций;
- подача и управление заявками;
- отзывы с рейтингом 1–10;
- указание результатов администратором;
- сводная таблица участников.

## Возможные улучшения

1. **Разделение прав по ролям** — использовать `Group` и `Permission` Django для ролей «Рецензент», «Модератор», «Автор».
2. **Расширенный профиль участника конференции** — по опыту практики 2.3 расширить пользователя через `AbstractUser` (организация, учёная степень).
3. **Загрузка файлов** — принимать тезисы докладов в виде файлов PDF/DOCX.
4. **Email-уведомления** — отправлять автору письмо при изменении статуса заявки.
5. **REST API** — реализовать API на Django REST Framework.
6. **Пагинация** — при большом количестве конференций добавить пагинацию.
7. **Поиск и фильтры** — добавить поиск по названию, фильтр по датам и тематикам.
8. **Тесты** — покрыть модели и представления модульными тестами.
