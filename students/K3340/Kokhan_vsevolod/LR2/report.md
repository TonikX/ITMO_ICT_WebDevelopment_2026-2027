# Лабораторная работа №2
## Простой сайт на Django

### Цель работы

Овладеть практическими навыками и умениями реализации веб-сервисов средствами Django.

**Вариант — «Табло победителей автогонок».**

---

### Используемые технологии

- Язык программирования: **Python 3.x**
- Веб-фреймворк: **Django**
- СУБД: **PostgreSQL**
- Система шаблонов Django (MTV)
- HTML / CSS
- **Bootstrap 5**

---

### Задание

Реализовать сайт с использованием фреймворка Django, архитектурного подхода MTV, системы шаблонов Django и базы данных в соответствии с выбранным вариантом и техническим заданием.

По варианту необходимо отображать информацию об участниках автогонок: ФИО участника, название команды, описание автомобиля, описание участника, опыт и класс участника.

Обязательный функционал:
- регистрация новых пользователей;
- просмотр автогонок и регистрация гонщиков;
- редактирование и удаление своих регистраций;
- написание отзывов и комментариев к автогонкам (тип, текст, рейтинг 1–10, автор, дата);
- указание времени заезда и результата через Django Admin;
- таблица заездов и результатов конкретной гонки;
- стилизация интерфейса;
- пагинация и фильтрация;
- разграничение прав администратора и пользователя в клиентском интерфейсе (`is_staff`).

---

### Описание предметной области

Веб-приложение предназначено для организации и отображения информации об автомобильных гонках.

Система хранит сведения о гонках, командах, автомобилях и гонщиках, принимает заявки на участие, обрабатывает их и показывает результаты заездов.

Категории пользователей:

- **Участник** — регистрируется, заполняет профиль гонщика, просматривает гонки, подаёт заявки, редактирует и удаляет свои заявки, оставляет комментарии.
- **Администратор** (`is_staff`) — управляет данными через Django Admin и клиентский интерфейс, подтверждает или отклоняет заявки, закрывает регистрацию на гонки, вносит результаты заездов.

---

### Реализованный функционал

#### 1. Регистрация и аутентификация

- создание учётной записи (имя, фамилия, email, телефон, логин, пароль);
- автоматическое создание профиля гонщика (`DriverProfile`);
- вход и выход из системы;
- просмотр и **редактирование** профиля гонщика (команда, автомобиль, описание, опыт, класс).

#### 2. Просмотр списка гонок

На странице списка гонок отображаются название, описание, место, дата начала, статус регистрации.

Дополнительно реализовано:
- **поиск** по названию и месту проведения;
- **фильтрация** по статусу регистрации (открыта / закрыта);
- **сортировка** по дате (возрастание/убывание) и по названию;
- **пагинация** (по 5 гонок на страницу).

#### 3. Регистрация на гонки

Авторизованный пользователь может подать заявку, если регистрация открыта и заявка ещё не подавалась.

Заявка сохраняется со статусом «На рассмотрении».

#### 4. Редактирование и удаление своих заявок

На странице «Мои заявки» пользователь может:
- **редактировать** заявку (комментарий), пока статус «На рассмотрении»;
- **удалить** заявку, если она не подтверждена.

Подтверждённые заявки удалять нельзя.

#### 5. Управление заявками (администратор)

Отдельная страница в клиентском интерфейсе (доступна при `user.is_staff`):
- просмотр всех заявок;
- подтверждение участия;
- отклонение заявки;
- возврат на рассмотрение.

Также доступна ссылка на Django Admin.

#### 6. Табло участников и результаты гонки

На странице конкретной гонки:

**Участники (подтверждённые заявки):**
- ФИО;
- название команды;
- автомобиль и его описание;
- описание участника;
- опыт (лет);
- класс (любитель / полупрофессионал / профессионал).

**Результаты заездов (таблица):**
- место;
- участник;
- команда;
- автомобиль;
- класс;
- опыт;
- номер заезда;
- время финиша;
- очки.

Время заезда и результат указываются администратором через **Django Admin** (модель `RaceResult`).

#### 7. Комментарии и оценки

После регистрации пользователь может оставить отзыв к гонке:
- тип (вопрос о сотрудничестве / вопрос о гонках / иное);
- текст;
- рейтинг от 1 до 10;
- дата и автор сохраняются автоматически.

Отображается список комментариев и средняя оценка гонки.

#### 8. Разграничение прав в клиентском интерфейсе

Через проверку `user.is_staff` в шаблонах:
- ссылки «Заявки участников» и «Администрирование»;
- кнопки добавления гонок;
- страница управления заявками.

Обычный пользователь этих элементов не видит.

#### 9. Стилизация

Интерфейс оформлен с помощью **Bootstrap 5** (навигация, карточки, таблицы, формы, бейджи статусов, пагинация).

### Структура базы данных

| Модель | Назначение |
|--------|------------|
| **User** | Пользователь (расширение `AbstractUser`, поле `phone`) |
| **Team** | Гоночная команда |
| **Car** | Автомобиль (марка, модель, номер, описание) |
| **DriverProfile** | Профиль гонщика (команда, авто, описание, опыт, класс) |
| **Race** | Гонка (название, место, даты, флаг открытой регистрации) |
| **Registration** | Заявка на участие (статус, дата, комментарий; уникальность driver+race) |
| **RaceResult** | Результат заезда (время, место, очки, номер заезда) |
| **Comment** | Комментарий к гонке (тип, текст, рейтинг 1–10, дата) |

Связи: `OneToOne` (User ↔ DriverProfile, Registration ↔ RaceResult), `ForeignKey` между остальными моделями. Ограничения целостности заданы через `UniqueConstraint` и `CheckConstraint`.

Взаимодействие с БД — через Django ORM.

### Запуск проекта

1. Перейти в корневую папку проекта.
2. Создать и активировать виртуальное окружение:

```bash
python -m venv venv
```

Windows PowerShell:

```powershell
venv\Scripts\Activate.ps1
```

3. Установить зависимости:

```bash
pip install -r requirements.txt
```

(или `pip install django`)

4. При использовании PostgreSQL — создать БД и прописать параметры в `config/settings.py`.  
   Для локального запуска можно использовать SQLite (блок в `settings.py`).

5. Миграции:

```bash
python manage.py makemigrations races
python manage.py migrate
```

6. Создать администратора:

```bash
python manage.py createsuperuser
```

7. Запуск:

```bash
python manage.py runserver
```

Сайт: http://127.0.0.1:8000/  
Админка: http://127.0.0.1:8000/admin/
