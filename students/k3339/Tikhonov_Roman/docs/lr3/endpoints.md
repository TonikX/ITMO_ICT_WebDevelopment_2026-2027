# ЛР3. Запросы и отчёты

Вариант задания определяет перечень возможных запросов и перечень возможных
отчётов. Каждому пункту соответствует отдельный GET-эндпоинт, доступный
после авторизации (заголовок `Authorization: Token <ключ>`).

## Перечень возможных запросов

### 1. Профессии соискателей, не представленные в вакансиях

`GET /api/analytics/professions-without-vacancies/`

Из справочника профессий выбираются те, что встречаются в резюме
соискателей, но не встречаются ни в одной вакансии.

```text
-> 200 [
  {"id": 7, "name": "Юрист", "description": "Правовое сопровождение"}
]
```

### 2. Все варианты вакансий для соискателей

`GET /api/analytics/matching-vacancies/`

Подбор: для каждого соискателя перечисляются открытые вакансии, где
совпадает профессия, уровень образования соискателя не ниже требуемого
(по полю priority справочника), стаж и разряд не меньше требуемых.

```text
-> 200 [
  {
    "applicant": {"id": 21, "last_name": "Морозова", "first_name": "Ольга",
                  "profession": 1, "education": 3, "experience_years": 0,
                  "rank": 4, "last_salary": "15000.00"},
    "matching_vacancies": []
  },
  {
    "applicant": {"id": 16, "last_name": "Петрова", "first_name": "Анна",
                  "profession": 3, "education": 5, "experience_years": 3,
                  "rank": 4, "last_salary": "90000.00"},
    "matching_vacancies": [
      {"id": 15, "status": "open", "salary_min": "45000.00", "salary_max": "60000.00", ...}
    ]
  }
]
```

Соискатель с пустым списком - тоже корректный результат: ни одна вакансия
не соответствует его требованиям.

### 3. Количество дней с момента предложения для незакрытых вакансий

`GET /api/analytics/offer-days/`

Берутся заявки открытых вакансий с заполненной датой предложения;
для каждой считается разница между текущей датой и датой предложения.

```text
-> 200 [
  {"applicant": "Иванов Пётр", "vacancy": "Повар @ ООО «Ромашка»",
   "offer_date": "2026-11-22", "days_since_offer": 3},
  {"applicant": "Петрова Анна", "vacancy": "Программист @ ООО «Ромашка»",
   "offer_date": "2026-11-11", "days_since_offer": 14},
  {"applicant": "Козлова Мария", "vacancy": "Бухгалтер @ ООО «Ромашка»",
   "offer_date": "2026-11-18", "days_since_offer": 7},
  {"applicant": "Смирнов Игорь", "vacancy": "Электрик @ АО «Вектор»",
   "offer_date": "2026-10-26", "days_since_offer": 30}
]
```

### 4. Количество пособий, выплачиваемых на текущий момент

`GET /api/analytics/active-allowances/`

Считаются пособия со статусом active (выплачивается).

```text
-> 200 {"active_allowances": 2}
```

### 5. Вакансии с высшим образованием, зарплата от 5000 до 60000

`GET /api/analytics/high-education-vacancies/`

Вакансия учитывается, если требуется высшее образование и вся зарплатная
вилка лежит внутри диапазона: salary_min >= 5000 и salary_max <= 60000.

```text
-> 200 {"vacancies_count": 1}
```

## Перечень возможных отчётов

### Для каждого предприятия - список открытых вакансий и их общее количество

`GET /api/reports/employers-open-vacancies/`

Обходятся все работодатели; для каждого возвращаются только его открытые
вакансии и их количество.

```text
-> 200 [
  {
    "employer": {"id": 6, "name": "ООО «Ромашка»", "contact_person": "Смирнова Анна", ...},
    "open_vacancies": [
      {"id": 15, "status": "open", "salary_min": "45000.00", "salary_max": "60000.00", ...},
      {"id": 16, "status": "open", "salary_min": "80000.00", "salary_max": "120000.00", ...},
      {"id": 17, "status": "open", "salary_min": "55000.00", "salary_max": "70000.00", ...}
    ],
    "open_vacancies_count": 3
  },
  {
    "employer": {"id": 7, "name": "АО «Вектор»", ...},
    "open_vacancies": [...],
    "open_vacancies_count": 4
  },
  {
    "employer": {"id": 8, "name": "ИП Смирнов А.В.", ...},
    "open_vacancies": [],
    "open_vacancies_count": 0
  }
]
```

Предприятие без открытых вакансий попадает в отчёт с пустым списком
и нулём - это тоже корректный результат.
