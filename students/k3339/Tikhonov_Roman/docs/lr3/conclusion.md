# ЛР3. Вывод

В системе один тип пользователя - инспектор биржи труда (учётные записи
Django/Djoser). Работодатели и соискатели - предметные сущности базы,
их данными управляет инспектор: классическая биржа труда принимает заявку
на вакансию от работодателя и регистрирует соискателя лично, личные
кабинеты участников не требуются. Операционные процессы - заявки, пособия,
направление на курсы - ведёт биржа, что отражено в правах: все процессы
доступны авторизованному инспектору.

Реализованы все требования задания: CRUD-операции для всех сущностей,
GET-запросы с вложенными объектами для связей "один ко многим" и
"многие ко многим", регистрация и авторизация по токенам средствами
Djoser, пять аналитических запросов и отчёт из варианта задания.

В ходе выполнения работы удалось научиться: переводить ER-схему в модели
Django ORM (связи ForeignKey и ManyToMany, политики удаления PROTECT и
CASCADE, ограничения уникальности, TextChoices) и работать с миграциями;
реализовывать REST API средствами Django REST Framework - сериализаторы
с валидацией и бизнес-правилами, вложенные сериализаторы, generic-классы
и APIView; настраивать регистрацию и авторизацию по токенам средствами
Djoser; подключать PostgreSQL к проекту Django; выполнять аналитические
запросы к данным средствами ORM (агрегация, аннотации, выражения F(),
prefetch_related) и оформлять документацию в MkDocs. Отдельно освоена
проверка API: работа с browsable API и HTTP-запросами с токеном.
