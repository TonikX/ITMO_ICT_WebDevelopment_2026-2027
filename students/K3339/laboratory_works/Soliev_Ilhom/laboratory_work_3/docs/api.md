# API

Коллекции поддерживают `GET` и `POST`, элементы — `GET`, `PUT`, `PATCH` и `DELETE`, если ниже не указано иное. Списки разбиты на страницы по 50 записей. Для всех `/api/` запросов отправляй заголовок `Authorization: Token <token>`.

## Регистрация и авторизация

| Метод | URL | Назначение |
|---|---|---|
| POST | `/auth/users/` | Регистрация работника (`username`, `email`, `password`) |
| POST | `/auth/token/login/` | Получение токена по имени пользователя и паролю |
| POST | `/auth/token/logout/` | Удаление текущего токена |
| GET | `/auth/users/me/` | Текущий пользователь и его роль |

Регистрация и получение токена доступны без авторизации; публичная регистрация создаёт роль `worker`. Создать директора можно в Django admin. Только директор может менять сведения о работниках, договорах и закреплениях работников.

## CRUD-коллекции

| URL | Сущность | Вложенные данные |
|---|---|---|
| `/api/workshops/` | Цехи | В списке цеха содержат клетки |
| `/api/cages/` | Клетки | Цех и текущие ID кур |
| `/api/breeds/` | Породы | Средние показатели породы |
| `/api/chickens/` | Куры | Порода, текущее назначение, последний зарегистрированный вес |
| `/api/weights/` | Измерения веса | — |
| `/api/chicken-cage-assignments/` | История пересадок кур | Курица, клетка, период |
| `/api/employees/` | Работники | Договоры и история закрепления за клетками; паспортные номера не выдаются |
| `/api/contracts/` | Трудовые договоры | Работник |
| `/api/employee-cage-assignments/` | Назначения работников | Работник, клетка, период |
| `/api/egg-records/` | Записи о яйцах | Курица |
| `/api/diets/` | Диеты | — |
| `/api/breed-season-diets/` | Диеты породы по сезону | Порода и диета |

`GET /api/workshops/` возвращает цехи с клетками (связь «один ко многим»). `GET /api/employees/` возвращает назначения работника на клетки (многие-ко-многим через сущность назначения).

Чтобы вывести курицу из учёта, отправь `POST /api/chickens/{id}/remove/` с датой и причиной:

```json
{"removed_at": "2026-10-31", "removal_reason": "sold"}
```

Директор увольняет работника через `POST /api/employees/{id}/dismiss/` с `ended_at` и `dismissal_reason`. Договоры и история назначений сохраняются; если после снятия работника занятую клетку некому обслуживать, API отклонит увольнение до переназначения клетки.

## Аналитика

Все методы ниже используют последний завершённый месяц, если месяц не задан. Параметр месяца имеет формат `YYYY-MM`.

| Метод | Назначение |
|---|---|
| `GET /api/analytics/chicken-eggs/?month=2026-10&breed_id=1&weight_min=1500&age_min=1` | Число яиц каждой курицы за месяц с фильтрами по породе, последнему весу на конец месяца и возрасту |
| `GET /api/analytics/top-workshop/?breed_id=1` | Цех или цехи с максимальным числом кур выбранной породы на сегодня; показывает все ничьи |
| `GET /api/analytics/worker-egg-average/?date_from=2026-10-01&date_to=2026-10-31` | Среднее число яиц на закреплённый рабочий день каждого работника |
| `GET /api/analytics/breed-workshop-counts/` | Число кур каждой породы в каждом цехе на сегодня |
| `GET /api/analytics/breed-comparison/?month=2026-10` | Сравнение средних показателей породы с фактическими средними по фабрике за месяц |
| `GET /api/analytics/monthly-report/?month=2026-10` | Отчёт по породам и цехам, числу кур на конец месяца и яйцам за месяц, а также итогам фабрики |

В методе по работникам вклад каждого закреплённого за клеткой работника равен количеству яиц этой клетки, делённому на число закреплённых работников в день сбора. Средняя производительность делится на число календарных дней выбранного периода, в которые работник был закреплён хотя бы за одной клеткой.

В месячном отчёте яйца относятся к цеху, в котором курица находилась в день сбора. Число кур берётся на последний день месяца. Средняя производительность в группе — яйца за месяц на одну курицу, находившуюся в группе на последний день месяца.
