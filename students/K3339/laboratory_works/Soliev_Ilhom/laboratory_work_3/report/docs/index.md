# Лабораторная работа 3 — Django ORM и REST API

## Цель работы

В лабораторной работе изучаются запросы Django ORM и разработка REST API на Django REST Framework. Она включает две практические работы и основное задание — серверную часть системы учёта птицефабрики.

## Практическая работа 3.1 — запросы Django ORM

В этой практике используются модели автомобилей, владельцев, водительских удостоверений и истории владения. Связь автомобиля с владельцем проходит через Ownership: промежуточная модель хранит даты владения, поэтому можно анализировать не только текущие связи, но и историю.

Например, владельцев красных автомобилей можно выбрать по обратной связи cars:

~~~python
owners = (
    CarOwner.objects
    .filter(cars__color__iexact="красный")
    .distinct()
    .order_by("last_name", "first_name")
)
~~~

distinct() убирает повтор владельца, если у него несколько красных автомобилей. Остальные запросы фильтруют машины по марке, ищут владельцев по имени и году начала владения, считают записи через Count и получают даты через Min и Max.

## Практическая работа 3.2 — Django REST Framework

API этой практики работает с воинами, профессиями и умениями. Профессия связана с воином отношением «один ко многим». Умения связаны отношением «многие ко многим», но для связи используется модель SkillOfWarrior, поскольку у каждого умения для конкретного воина есть собственный уровень.

~~~python
skills = models.ManyToManyField(
    Skill,
    through="SkillOfWarrior",
    related_name="warriors",
)
~~~

Сериализаторы формируют ответы API и проверяют входные данные. Представления предоставляют операции для списков и отдельных объектов; отдельный маршрут возвращает воинов вместе с их умениями.

## Основное задание — вариант 7 «Птицефабрика»

Основное приложение моделирует работников и трудовые договоры, цехи и клетки, породы и кур, измерения веса и яйценоскости, перемещения кур, закрепления работников и сезонные диеты. Назначения кур и работников представлены отдельными моделями с датами начала и окончания — так в базе сохраняется история изменений.

API построено на Django REST Framework и использует токенную авторизацию. Обычный авторизованный пользователь может просматривать данные, а для ряда кадровых операций — например, изменения работников и договоров — требуются права директора. Проверка вынесена в отдельный класс разрешений:

~~~python
class DirectorOrReadOnly(BasePermission):
    def has_permission(self, request, view):
        if request.method in SAFE_METHODS:
            return bool(request.user and request.user.is_authenticated)
        user = request.user
        return bool(
            user
            and user.is_authenticated
            and (user.is_superuser or getattr(user, "role", None) == "director")
        )
~~~

Сериализаторы проверяют поля запросов, а сервисный слой — предметные правила: вместимость клетки, отсутствие пересекающихся назначений и наличие работника для занятой клетки. Изменения нескольких связанных записей выполняются в транзакциях, чтобы ошибка не оставила данные в частично обновлённом состоянии.

Аналитические методы рассчитывают количество яиц по фильтрам, определяют цеха с наибольшим числом кур заданной породы, считают среднюю яйценоскость на работника и сравнивают показатели пород. Например, месячный отчёт доступен через GET /api/analytics/monthly-report/?month=2026-10; параметр задаёт отчётный месяц.
