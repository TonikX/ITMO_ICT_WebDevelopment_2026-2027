# Практическая работа 3.2 — Django REST Framework

Проект демонстрирует сериализаторы и REST API для воинов, профессий и умений. Схема включает `Warrior`, `Profession`, `Skill` и ассоциативную модель `SkillOfWarrior`; поле `level` в ассоциативной модели хранит уровень владения умением.

## Запуск

Из этой папки:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py seed_demo_data
python manage.py runserver
```

В оболочке fish активируй окружение командой `source .venv/bin/activate.fish`. Для Windows: `.venv\\Scripts\\activate`.

В проекте используются англоязычные демонстрационные данные по героям Marvel. Если в SQLite уже лежит предыдущая демонстрационная база, команда `python manage.py seed_demo_data --reset` очистит все данные практики 3.2 и создаст набор Marvel заново. Не используй `--reset`, если в этой базе есть нужные тебе записи.

DRF browsable API доступен по адресу `http://127.0.0.1:8000/api/`. Корень API показывает ссылки на основные коллекции. Просмотр, создание и изменение данных открыты без авторизации для учебной практики.

Чтобы открыть Django admin, создай администратора командой `python manage.py createsuperuser`, затем перейди на `http://127.0.0.1:8000/admin/`.

## Эндпоинты

| Метод | URL | Назначение |
|---|---|---|
| GET | `/api/skills/` | Список умений |
| POST | `/api/skills/` | Создание умения |
| GET/PUT/DELETE | `/api/skills/<id>/` | Просмотр, изменение и удаление умения |
| GET/POST | `/api/professions/` | Список профессий и создание профессии |
| GET/PUT/DELETE | `/api/professions/<id>/` | Просмотр, изменение и удаление профессии |
| GET | `/api/warriors/` | Все воины с вложенными профессиями |
| POST | `/api/warriors/` | Создание воина и его связей с профессией и умениями |
| GET | `/api/warriors/with-skills/` | Все воины с вложенными умениями |
| GET | `/api/warriors/<id>/` | Воин с профессией и умениями |
| PUT | `/api/warriors/<id>/` | Полное изменение воина и списка его умений |
| DELETE | `/api/warriors/<id>/` | Удаление воина |

Для `POST /api/warriors/` тело запроса может выглядеть так:

```json
{
  "name": "Tony Stark",
  "race": "h",
  "level": 91,
  "profession": 1,
  "skills": [
    {"skill": 1, "level": 7},
    {"skill": 2, "level": 100}
  ]
}
```

Перед отправкой запроса посмотри актуальные идентификаторы профессий и умений через `GET /api/professions/` и `GET /api/skills/`. Значения `race`: `h` — Human, `a` — Asgardian, `m` — Mutated Human, `s` — Synthetic, `k` — Kree-Human Hybrid.

Для изменения воина отправь `PUT` на `/api/warriors/<id>/` с полным телом запроса:

```json
{
  "name": "Tony Stark",
  "race": "h",
  "level": 92,
  "profession": 1,
  "skills": [
    {"skill": 2, "level": 9}
  ]
}
```

При полном `PUT` отсутствие `skills` очищает список умений, а отсутствие `profession` сбрасывает профессию. `DELETE /api/warriors/<id>/` удаляет выбранного воина и его связи с умениями.

## Покрытие задания

- Добавление и просмотр умений реализованы через `APIView`, как показано в практике.
- Списки воинов возвращают вложенные профессии и умения отдельными запросами.
- Карточка воина возвращает профессию и умения с уровнем владения.
- Для воина доступны все операции CRUD, включая POST-создание, которое не было отдельно перечислено в буллетах задания, но требуется для полного CRUD.
- Профессии также можно создавать и редактировать через API, чтобы настроить вложенную связь без Django admin.
- DRF generic views обрабатывают валидацию сериализаторов и стандартные HTTP-статусы.
- Назначение умения одному воину уникально; повторный skill ID в одном запросе отклоняется.
- Создание и замена связей умений выполняются в транзакции, поэтому частичный результат не сохраняется при ошибке.

`seed_demo_data` можно запускать повторно: демонстрационные записи обновляются по стабильным ключам, новые дубликаты связей умений не создаются.
