# Проверки ЛР2

Проверено 14 октября 2026 года на macOS, Python 3.10.22, Django 3.2.25,
Jinja2 3.1.6 и PostgreSQL 15.17 с UTF-8 локалью. SQLite не использовалась.

## Автоматические проверки

В папке каждого проекта:

```sh
python manage.py test -v 2
```

| Проект | Результат | Проверяемые сценарии |
| --- | --- | --- |
| ЛР2 | 10 тестов — OK | Регистрация, вход, POST-выход, создание/изменение/удаление бронирования, чужие id, неверные даты, вместимость, соприкасающиеся периоды, права сотрудника, операции в админке, отзывы и рейтинг, экранирование HTML, постояльцы за месяц, русский поиск, фильтры, пагинация и CSRF |
| Практики | 3 теста — OK | Расширенный пользователь и форма, автомобильный CRUD, M2M through, пересечение дат, дополнительные поля в админке |

Отдельный TransactionTestCase отправляет два одновременных запроса бронирования
одного номера. Проверяется результат: один POST сохраняет запись и возвращает 302,
другой возвращает форму с ошибкой; в базе остаётся одно бронирование.

Логи: [лабораторная](lab-tests.txt), [практики](practice-tests.txt).

`manage.py check` не обнаружил ошибок. `makemigrations --check --dry-run`
не обнаружил несохранённых изменений моделей. `docker compose config --quiet`
подтвердил корректность конфигурации PostgreSQL.

## Проверка в браузере

Проверены реальные страницы на локальных серверах `9020` и `9021`:

- Русский поиск без учёта регистра и пагинация каталога.
- Регистрация, бронирование, изменение и удаление через формы.
- Заселение и выселение сотрудником, таблица постояльцев, админка.
- Добавление и отображение отзыва с рейтингом и датами.
- Три владельца и три автомобиля через формы практик; изменение и удаление CBV.
- Два владельца и четыре автомобиля через Django-admin, каждому назначены три автомобиля с непересекающимися периодами владения.
- Каталог при ширине 390 px без горизонтального переполнения.

Ошибок JavaScript и ответов HTTP 5xx при проходе не обнаружено.
[Лог браузерной проверки](browser-checks.txt). Скриншоты находятся на страницах
[интерфейсов](interfaces.md) и [практик](practice.md).
